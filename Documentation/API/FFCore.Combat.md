## FixedPointGridRay

```csharp
public static class FixedPointGridRay
```

The pure fixed-point ray-vs-tile cell walk: the deterministic replacement for the float `CollisionWorld` raycast the legacy avoidance path probes with. It answers ONE question — which lattice cells does the segment `start → end` cross, in order, and through which face — and knows nothing about entities, blockers, ignore policy or response.

| Member | Summary |
|---|---|
| `public const int MaxCells = 512` | Hard bound on cells emitted by one walk. The production probe is one heartbeat of travel plus a 1/60-second margin, so even a 1000 u/s mover at 16 UPS crosses ~9 tiles; the cap only exists so a pathological segment cannot spin, and truncation is deterministic (the walk simply stops, which reads as "no blocker beyond here"). |
| `public static fp CellLowerBound(int cell, int tileLength)` | The lower world coordinate of `cell` on one axis. |
| `public static int ToCell(fp world, int tileLength)` | Signed world-to-lattice conversion: `floor(world / tileLength)`, correct on both sides of the origin. `GridHelper.SnapToGrid(fp3)` does the same floor for the production tile lookup; this is the scalar form the walk needs, kept here so FFCore owns the arithmetic the traversal is defined in terms of. |
| `public static int Traverse(fp3 start, fp3 end, int gridHeight, int tileLength, ref NativeList<GridRayCell> cells)` | Convenience form for tests and any caller that wants the whole ordered crossing list rather than the allocation-free `GridRayWalker` the production adapter uses. Returns the number of cells appended. |

## GridRayCell

```csharp
public struct GridRayCell
```

One cell a `GridRayWalker` crossed, in ray order.

| Member | Summary |
|---|---|
| `public int3 Cell` | Tile coordinate: `x`/`z` are floor-divided lattice indices, `y` is the walk's grid height level. |
